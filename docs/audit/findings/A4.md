## Credential, log, subprocess

- Không đọc/lưu token CLI (đúng với docstring cli_login/cli_auth); `cli_env()` bỏ các biến API key (bất biến 1); token Google mã hóa DPAPI trên Windows, trên non-Windows lưu `plain:` (P3; file đã chmod 600 ở store.py:190). Access log che `code/state/token` (`utils/middleware.py:25-68`); log callback không in code; `grep logger` trong `connections/` chỉ có autobind (tên model, id kết nối). Không thấy token/OAuth code lọt vào log.
- `_CODE_RE` chặn ký tự điều khiển trước khi ghi vào stdin CLI; lệnh CLI chạy bằng argv, không shell.
- `kill_process_tree` (taskkill /T, killpg) đúng; lỗ hổng duy nhất là A4-4.
- Google OAuth cần `client_secret` từ env: là secret của OAuth app, không phải API key model; `test_no_model_api_keys.py` vẫn là hàng rào.

## Tóm tắt

Phần credential và log khá sạch: không lưu token CLI, che query nhạy cảm, đóng cây tiến trình đúng cách. Hai vấn đề cần sửa trước là A4-1 (provider openai âm thầm chạy trên Claude kèm đổi model, trái docstring) và A4-2 (xóa kết nối cuối đăng xuất CLI toàn máy; chữ xác nhận không chính xác, toast bỏ qua `cliLoggedOut`). Kèm theo là A4-3, một bug chi phí mới: node không khai `provider` bị ghi đè model thành model đắt nhất của catalog. Hành vi đề xuất: bind theo vendor trước, default sau; xóa kết nối chỉ gỡ bản ghi, đăng xuất CLI là lựa chọn rõ ràng mặc định tắt; judge Lab theo default, ưu tiên vendor khác workflow, bỏ qua CLI đã đăng xuất. Các mục SUSPECTED (A4-5, A4-7) cần test đỏ hoặc ảnh chụp trước khi sửa. Test sketch: A4-1 (2 kết nối, provider openai -> connection codex), A4-3 (không provider giữ name), A4-4 (shutdown giết session).
